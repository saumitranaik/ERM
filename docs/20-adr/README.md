# 20 — Architecture Decision Records

## Purpose

Records significant, hard-to-reverse architecture decisions with their context and
consequences, so future sessions don't relitigate settled questions.

## What belongs here

- One ADR per decision: `NNNN-kebab-case-title.md`, four-digit sequence, monotonic across
  the whole repository, never reused or renumbered, following the standard ADR shape
  (Status, Context, Decision, Consequences)
- ADRs should be written so they could be adopted into PRSMTD's own ADR Traceability Matrix
  (`system.md §20`) without rework if the decision requires PRSMTD changes

## Cross-references

- Every ADR should reference the spec(s) it decides on and be referenced back from them
- [`../22-traceability/`](../22-traceability/) — ADR ↔ capability traceability
- `PRSMTD/docs/authoritative/system.md §20` — ADR Traceability Matrix doctrine this should interoperate with
